# Этап: dashboard преподавателя

Дата: 20 октября 2026 года. Ветка: `devRem`.

## Реализовано

- Dashboard приведён к композиции `01_dashboard_graphite.png`: заголовок с датой по Москве, четыре KPI, компактное расписание дня, ближайшее занятие и три последних уведомления.
- Удалены неутверждённые «быстрые действия», формы приглашения и пробные заявки с главной страницы. Приглашение ученика остаётся в действующем разделе «Ученики», пробные заявки — в отдельном разделе.
- KPI формируются backend из реальных данных:
  - занятия текущего дня без отменённых;
  - ожидающие решения заявки об оплате;
  - ответы на домашние задания, отправленные сегодня;
  - активные запросы переноса в статусах `PENDING` и `COUNTER_OFFER`.
- Backend возвращает ближайшее запланированное занятие и готовый список занятий дня. Все выборки ограничены текущим преподавателем через урок или связанного ученика.
- Действующая модель ДЗ не расширялась: KPI считает принятые сегодня ответы, новый статус «на проверке» не добавлялся.
- Карточки используют фактические ФИО, темы, время, длительность, статусы и ссылки подключения. При отсутствии данных показываются честные пустые состояния.
- Добавлена адаптивная раскладка dashboard для телефона.

## Проверки

- Backend: Ruff и strict mypy — успешно.
- Полный `pytest` — успешно, включая новый интеграционный сценарий трёх ненулевых KPI.
- Frontend: Biome — успешно; 5 файлов / 7 тестов — успешно.
- Production build Next.js — успешно, 22 маршрута.
- Проверка через реальный Next.js proxy и PostgreSQL: `/api/v1/teacher/dashboard` и `/teacher` вернули `200`; SSR содержит «Сегодняшнее расписание» и не содержит «Быстрые действия».

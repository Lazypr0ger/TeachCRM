# Журнал этапов

## Этап 0 — каркас

Статус: завершён 2026-10-17.

Цель: воспроизводимый локальный запуск frontend, backend, worker, PostgreSQL и S3-эмулятора; миграционная основа, healthchecks, базовые дизайн-токены и CI-ready команды проверок.

Миграции: `20261017_0001` — расширения PostgreSQL `citext`, `btree_gist`, `pgcrypto`.

Проверено:

- backend: Ruff, strict mypy, 2 pytest;
- frontend: Biome, Vitest, production build, `npm audit` без уязвимостей;
- Compose: PostgreSQL healthy, миграция exit 0, API healthy, worker запущен, S3 running, web отвечает;
- `/health/live` и `/health/ready` возвращают успешный ответ;
- миграционные расширения присутствуют в PostgreSQL.

## Этап 1 — авторизация и роли

Статус: завершён 2026-10-17.

Реализованы bootstrap единственного преподавателя, создание ученика с ручным приглашением, активация, вход и выход, server-side sessions, абсолютный/idle TTL, CSRF, роли, блокировка с отзывом сессий, запросы и одноразовые ссылки восстановления пароля. Добавлены страницы входа, активации, восстановления, защищённые кабинеты и форма создания приглашения.

Миграции: `20261017_0002` — users, минимальные student profiles, sessions, invitation/reset tokens, reset requests, login attempts и audit log.

Проверено: 8 pytest, негативные role/CSRF сценарии, одноразовые токены, отзыв сессий, полный upgrade/downgrade PostgreSQL, production build frontend и сквозной API smoke flow.

## Этап 2 — ученики и занятия

Статус: завершён 2026-10-19.

### Срез 2.1 — управление учениками

Статус: завершён 2026-10-17.

Реализованы защищённые teacher API и интерфейс списка учеников: поиск по ФИО/логину, фильтры по классу и статусу, сортировка, пагинация, просмотр и редактирование карточки, повторное приглашение и блокировка с отзывом сессий. Из персональных данных сохраняются только ФИО и класс. Изменения карточки записываются в audit log.

Новая миграция не требуется: срез использует таблицы `users` и `student_profiles` из `20261017_0002`.

Проверено: 12 pytest, Ruff, strict mypy, Biome, Vitest и production build Next.js.

### Срез 2.2 — индивидуальные уроки

Статус: завершён 2026-10-19.

Реализованы создание, просмотр, редактирование, отмена и идемпотентное завершение индивидуального урока. Teacher видит общее расписание с фильтрами и пагинацией; student получает только собственные уроки и ближайшее занятие на Dashboard. Ссылки подключения разрешены только по HTTPS, время вводится и показывается в `Europe/Moscow`.

Миграция `20261019_0003` создаёт `lessons`, проверяет корректность интервала и защищает расписание PostgreSQL exclusion constraints для преподавателя и ученика. Интервалы полуоткрытые: соседние уроки разрешены, пересекающиеся возвращают `409`. Редактирование использует version и блокировку строки против устаревших конкурентных изменений.

Проверено: 18 pytest, негативные RBAC/ownership-сценарии, прикладные конфликты, прямое отклонение пересечения PostgreSQL, downgrade/upgrade миграции, Ruff, strict mypy, Biome, Vitest и production build Next.js.

Повторения, A/B-недели, доступность и переносы относятся к этапу 3 и в этом срезе не начаты.

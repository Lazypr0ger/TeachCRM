# Безопасность v1

## Реализовано на этапе авторизации

- Пароли хешируются Argon2id и не возвращаются API.
- Сессия использует случайный непрозрачный токен; в PostgreSQL хранится только SHA-256 hash.
- Session cookie имеет `HttpOnly`, `SameSite=Strict`, а в production также `Secure`.
- Изменяющие авторизованные запросы требуют отдельный CSRF-токен.
- Для сессий действуют абсолютный и idle TTL. Смена пароля и блокировка ученика отзывают все его сессии.
- Приглашения и ссылки восстановления одноразовые, имеют TTL и хранятся только в виде hash.
- Публичной регистрации нет. Роль и служебные поля отсутствуют в student DTO.
- Teacher API проверяет роль на backend; STUDENT получает `403` даже при прямом запросе.
- Ошибка входа одинакова для отсутствующего пользователя и неверного пароля. После пяти ошибок за 15 минут действует временное ограничение.
- Создание ученика, активация, блокировка и восстановление записываются в audit log без токенов и паролей.
- Student API уроков всегда выводит профиль из текущей серверной сессии и не принимает произвольный `student_id`; запрос чужого урока возвращает 404 без метаданных.
- Пересечения активных уроков проверяются сервисом и двумя PostgreSQL exclusion constraints. Ссылки подключения принимаются только с HTTPS.
- Изменять недельную доступность и приватные причины исключений может только преподаватель. Ученик управляет только собственными отметками доступности; чужой идентификатор не принимается API.
- Пересекающиеся разовые исключения преподавателя и отметки ученика отклоняются сервисом и PostgreSQL exclusion constraints. Приватная причина блокировки отсутствует в student API.
- Экземпляры повторяющейся серии защищены уникальным ключом в PostgreSQL. Создание серии выполняется одной транзакцией, а индивидуальные изменения и отмены сохраняются как исключения и не перезаписываются worker.
- Student API переносов выводит профиль из текущей сессии; чужой запрос возвращает `404`. Перенос не доверяет ранее проверенному слоту: при принятии сервер повторно блокирует данные, проверяет доступность/пересечения и атомарно обновляет урок.
- Материалы хранятся в приватном S3 bucket и выдаются только через API после серверной проверки доступа к уроку. Ключи хранилища не возвращаются клиенту.
- Сервер проверяет размер, расширение и сигнатуру PDF/PNG/JPEG/WebP/DOCX. Для DOCX дополнительно ограничены число элементов, распакованный объём и степень сжатия; SVG запрещён. Истёкшие временные загрузки удаляет worker.
- Черновые файлы ответа доступны только создавшему их ученику. Финальная отправка атомарно связывает их с единственным submission; преподаватель получает доступ после отправки. Повторный запрос защищён idempotency key, а чужие уроки, задания и файлы скрываются ответом `404`.
- Тариф, режим оплаты, день платежа и семейную скидку изменяет только преподаватель через CSRF-защищённый API. Версия записи предотвращает потерю параллельных изменений; каждое создание и изменение попадает в audit log.
- Student API начислений всегда выводит профиль из текущей сессии и не принимает произвольный `student_id`. Снимки суммы и скидки invoice не меняются после изменения тарифа; повторное завершение урока защищено уникальным ограничением от двойного начисления.
- Сообщение «Я оплатил» не меняет полученные средства. Подтверждение доступно только преподавателю, блокирует claim и invoice, ограничивает сумму текущим остатком и защищено idempotency key. Для invoice разрешён только один `PENDING` claim, а чужой invoice возвращает ученику `404`.
- Подтверждённые платежи не удаляются и не редактируются. Исправление оформляется отдельной обратной операцией с обязательной причиной, уникальной ссылкой на оригинал, idempotency key и audit log; повторная отмена запрещена.

## Локальное восстановление

Ученик создаёт запрос на странице восстановления. Преподаватель видит запрос через API и создаёт одноразовую ссылку, которую передаёт вручную. Если преподаватель потерял доступ, локальный оператор выполняет:

```bash
cd backend
uv run python -m app.cli issue-password-reset --login teacher
```

MFA преподавателя требуется перед публичным production-запуском и остаётся отдельным release gate.
